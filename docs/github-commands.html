Commands for routine use

The commands you'll use day-to-day: saving work, managing branches, and recovering from mistakes. Open a terminal in the project folder to run any of these.

💾

Saving your work (commits)

A commit is a permanent snapshot. You stage the files you want to include, write a short message explaining what changed, then save. Think of it as "Save + label + submit to the archive."

See what's changed Always start here — shows which files are new, modified, or deleted before you commit anything.
$git status
Stage files for the commit Choose what to include. Stage specific files, or stage everything that's changed.
$git add filename.py
# stage one specific file
$git add .
# stage everything changed (use with care — run git status first)
Create the commit Write a short, plain-English message saying what changed and why. Keep it to one sentence.
$git commit -m "add character scraper for Fandom wiki"
Push to GitHub Sends your committed changes up to the remote repository so the team can see them.
$git push
💡
Commit little and often. Small, focused commits are easier to review and much easier to undo if something goes wrong. One clear change per commit beats a massive catch-all commit.
🌿

Branches

A branch is a safe copy of the project to work in. Changes on a branch don't affect main until you deliberately merge them. Use a branch for any piece of work that takes more than one sitting.

Create a new branch and switch to it Name branches by what you're working on, using hyphens. Always branch off from main.
$git switch -c stage-2-database
# creates the branch and moves you onto it in one step
See which branch you're on The branch with an asterisk (*) is the one you're currently working on.
$git branch
Switch to an existing branch
$git switch stage-2-database
Push a new branch to GitHub The first time you push a new branch, you need to tell git where it lives remotely.
$git push -u origin stage-2-database
# after this, plain "git push" works on that branch
Merge a branch into main Switch to main first, then merge. Do this when the work on the branch is complete and tested.
$git switch main
$git merge stage-2-database
Delete a branch after merging Once merged, the branch is no longer needed. Clean it up locally and on GitHub.
$git branch -d stage-2-database
# local delete
$git push origin --delete stage-2-database
# remote delete
⚠️
Never commit directly to main. Always work on a branch. The main branch is the live, tested version — treat it as sacred.
🔧

Fixing mistakes

Git keeps a full history, so very little is truly lost. The right command depends on how far along the mistake got.

Unstage a file (before committing) You ran git add but changed your mind about including a file in the next commit.
$git restore --staged filename.py
Discard changes to a file (before committing) Throws away all edits to a file and restores it to how it was at the last commit. This cannot be undone.
$git restore filename.py
Undo the last commit (keep the changes) Removes the commit but leaves your file edits intact so you can fix the message or stage different files.
$git reset --soft HEAD~1
Safely undo a commit that's already been pushed Creates a new commit that reverses the effects of a previous one — the safe option when the mistake is already on GitHub. Find the commit hash with git log.
$git log --oneline
# find the hash of the commit you want to undo (e.g. a3f1c22)
$git revert a3f1c22
$git push
Stash changes temporarily Saves your in-progress work without committing it, so you can switch to another branch and come back later.
$git stash
# saves and clears your working changes
$git stash pop
# brings them back when you're ready
✅
When in doubt, don't guess. Run git status first to understand the current state, then decide. Most mistakes are easy to fix — but the wrong recovery command can make things worse.
🗺️

Common scenarios end-to-end

Full command sequences for the most frequent situations.

Starting a new piece of work
Beginning a new stage or feature
1
Make sure main is up to date
git switch main git pull
2
Create and switch to a new branch
git switch -c stage-3-scrapers
3
Do your work, then commit as you go
git add . git commit -m "add fandom wiki scraper skeleton"
4
Push the branch to GitHub
git push -u origin stage-3-scrapers
Submitting your work for review (Pull Request)
Your branch is ready — open a PR so Ash can review and approve it before it goes into main
1
Push your branch to GitHub (terminal)
git push -u origin your-branch-name
If you've pushed before, plain git push is enough.
2
Open a Pull Request (GitHub website) Go to github.com/Ash-ash-in/trivia-games. You'll see a yellow banner: "Compare & pull request" — click it. If the banner isn't there, click the Pull requests tab → New pull request.
3
Fill in the PR details (GitHub website) Give it a clear title (e.g. "Add Fandom wiki scraper"). Add a short description of what you did and anything Ash should know. On the right-hand side, under Reviewers, click the gear icon and select Ash.
4
Click "Create pull request" and wait (GitHub website) GitHub will notify Ash. The PR page shows a yellow "Review required" status — this is normal. You cannot merge until Ash approves.
5
After approval — merge (GitHub website) Once Ash approves, a green "Merge pull request" button appears. Click it, then "Confirm merge". Your changes are now in main. GitHub will offer to delete the branch — click "Delete branch" to keep things tidy.
Reviewing and approving a PR (Ash)
Someone has opened a PR and is waiting for your sign-off
1
Open the PR (GitHub website) Click the Pull requests tab on the repo. Open the PR. The Files changed tab shows exactly what was added or removed — green lines are additions, red are deletions.
2
Leave comments if needed (GitHub website) Click any line in Files changed to leave an inline comment. Use the Conversation tab for general notes. The author will be notified and can push fixes to the same branch — the PR updates automatically.
3
Approve and merge (GitHub website) Click Review changes (top right of Files changed) → select Approve → Submit review. Then scroll down to the green merge button and confirm. Delete the branch when prompted.
4
Pull the updated main locally (terminal)
git switch main git pull
Merging directly into main (Ash only)
Ash can bypass the PR requirement as repo admin — use for small, low-risk changes
1
Switch to main and pull
git switch main git pull
2
Merge your branch
git merge your-branch-name
3
Push and clean up
git push git branch -d your-branch-name git push origin --delete your-branch-name
I committed something I shouldn't have
The bad commit hasn't been pushed yet
1
Undo the commit, keep the file changes
git reset --soft HEAD~1
2
Fix whatever was wrong, then re-commit
git add . git commit -m "correct description of what this actually does"
