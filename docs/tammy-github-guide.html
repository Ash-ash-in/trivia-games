GitHub for Tammy

Everything you need to know to use GitHub on this project — no coding required. Keep this page bookmarked.

🏠 What is GitHub?

GitHub is where all the project's code and files live. Think of it like a shared Google Drive for code — but with one important extra feature: it keeps a complete history of every change ever made, who made it, and why.

You won't need to understand any of the code itself. Your job on GitHub is to see what's happening, review notes, and occasionally leave feedback on specific issues.

💡
The project lives here: github.com/Ash-ash-in/trivia-games — bookmark this link. You'll come back to it often.

🎨 Your role on GitHub

Here's what you'll actually use GitHub for on this project:

Reviewing what's been built

After Ash completes a stage, you can browse the files to see what was added and read Ash's notes explaining each change.

Reading and commenting on issues

Issues are like a to-do list and discussion board. Some issues will be flagged specifically for your review — for example, uncertain facts that need a human Simpsons expert to resolve.

Signing off on completed stages

At the end of each project stage, Ash will point you to a specific issue or page to confirm you're happy before work moves on.

✅
You will never need to edit code. If you're ever looking at a screen full of unfamiliar symbols, you've gone somewhere you don't need to be — close the tab and ask Ash.

📁 Viewing project files

The main page of the repo shows you a list of folders and files, like a file explorer. You can click into any folder or file to read it.

1
Go to the project page

Open github.com/Ash-ash-in/trivia-games in your browser.

2
Browse the folders

You'll see folders like docs and data. Click any folder to open it, and click any file to read it.

3
Look for the docs folder first

The docs folder contains plain-English guides written for both of us. That's your home base.

💡
Use the breadcrumb trail at the top of any page to find your way back — it shows you exactly where you are in the folder structure.

📋 Seeing what changed recently

Every time Ash saves new work, it's recorded as a "commit" — a snapshot with a short note explaining what changed. You can read these like a project diary.

1
Find the commits list

On the main project page, look for a clock icon near the top right of the file list. It shows the number of commits. Click it.

2
Read the commit messages

Each entry has a short title (the commit message) and a date. These are written in plain English and tell you what Ash was working on.

3
Click a commit to see the detail

You'll see green lines (added content) and red lines (removed content). You don't need to understand the code — the commit message at the top explains the purpose.

🎫 Issues & tickets

The Issues tab is the project's built-in discussion board. It's used for tracking tasks, flagging uncertain facts, and leaving feedback. Think of each issue as a Post-it note on a shared noticeboard.

1
Click the Issues tab

It's near the top of the project page, next to Code and Pull requests.

2
Look for issues tagged "needs-tammy"

Ash will label issues that need your attention with a coloured tag. Click the issue title to open it and read the full context.

3
Leave a comment to respond

Scroll to the bottom of the issue. There's a text box — type your response and click Comment. You can use plain English, no formatting needed.

4
Close the issue when resolved

If you've answered the question or confirmed the fact, click Close issue at the bottom. Ash will re-open it if more is needed.

⚠️
Accuracy issues are high priority. When Ash flags an issue as a fact that needs verifying, treat it as urgent — a wrong answer on the quiz site loses us players permanently.

⬇️ Downloading a file

If Ash creates a document or image you want to save to your computer:

1
Open the file

Navigate to it through the folders and click the filename.

2
Click the download button

Look for a small download icon (an arrow pointing down) near the top-right of the file view, or right-click and choose "Save as".

📖 Glossary

A quick reference for the words you'll see on GitHub most often.

repository
The project's home on GitHub — all files, history, and discussions in one place. Often called a "repo" for short.
commit
A saved snapshot of work. Like hitting Save, but it also stores a note about what changed and creates a permanent record.
branch
A separate copy of the project where Ash can try something new without affecting the main version. Changes get merged back when they're ready.
main
The official, current version of the project. What's on main is what's live (or will be).
issue
A discussion thread attached to the project. Used for tasks, bug reports, fact-checking requests, or any question that needs a decision.
label
A coloured tag on an issue that categorises it — for example "needs-tammy", "bug", or "accuracy".
README
A plain-English introduction to the project, shown automatically on the main page. Start here if you're ever lost.
